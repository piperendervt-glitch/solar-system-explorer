## 単位の導出（**どの設定値からそう言えるのか**）
############################################################

-- 2 つのアセットの設定は同一 --
  項目 / ステーション (Cobble) / コックピット (Hi-Rez)
  FBX UnitScaleFactor : 1 / 1
  useFileScale        : True / True
  globalScale         : 1 / 1
  fileScale           : 0.01 / 0.01
  プレハブ側の最も多い倍率 : 100 / 1
  プレハブのルート localScale : (1.0000, 1.0000, 1.0000) / (1.0000, 1.0000, 1.0000)

-- 導出（掛け算） --
  FBX の UnitScaleFactor = 1 は「1 ファイル単位 = 1 cm」の申告。
  useFileScale = True なので Unity は fileScale = 0.01 を掛けて
  メッシュをメートルに直す。**取り込み後のメッシュはメートル。**

  ステーション : メッシュ [m] x プレハブ倍率 100 -> プレハブ単位
  コックピット : メッシュ [m] x プレハブ倍率 1 -> プレハブ単位

  ルートの localScale は両方とも 1 なので、**プレハブをシーンへ scale 1 で置いたときの寸法 = 上の bbox。**
  Unity の慣習では 1 unit = 1 m なので、その bbox の数値がそのままメートルになる。

-- 裏取り: 同じ設定のコックピットで寸法が実物大か --
  **コックピットは Demo 3 で実機に映しており、人が座る寸法として成立していることが分かっている。** そのアセットが
  ステーションと同一の FBX 単位申告・同一のインポータ設定で、
  プレハブ倍率だけが違う。だから同じ換算が両方に効く。

  コックピットの実測（プレハブ単位 = メートルと読んだとき）:
    機体 (Cockpit3_Body) : 1.6075 x 1.6312 x 5.7662 m
    座席 (CockpitEquipments_Seat) : 0.6899 x 1.1755 x 1.0748 m
    ボタン (CockpitEquipments_Button6-1) : 0.0224 x 0.0058 x 0.0224 m

-- 結論 --
  **ステーションのプレハブ単位は Unity のメートル。**
  scale 1 で置いたときの実寸 = 41.94 x 24.84 x 62.54 m

-- **この導出が抱えている食い違い（隠さない）** --
  FBX の申告（UnitScaleFactor = 1 = cm）を額面どおりに読むと、
  ステーションは 41.94 **cm** になる。プレハブの x100 は
  インポータの x0.01 をちょうど打ち消しており、**結果としてプレハブは FBX の生の数値をそのまま再現している。**
  つまり作者は「生の数値をメートルとして扱う」つもりで作り、
  FBX の単位申告のほうが実態と合っていない（書き出し時のよくある不一致）。

  **確定できるのは「scale 1 で置くと Unity 単位で何になるか」まで。**
  それがメートルであることは Unity の慣習と、同設定のコックピットが実物大であることから来ている。
  **作者が 41.94 m を意図した、という一次資料は持っていない**（デモシーンは 13-2 で取り込まずに落とした）。

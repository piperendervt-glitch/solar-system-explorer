## 1. 前提（現状の構成と守ること）

- ステーションは箱＋円筒のプリミティブ。地球中心から 12,000 units / 火星中心から 8,000 units、位相角 90 度、ポート正面 −Y、許容角 30 度、PortStandoff 0.3 units、要求可能距離 20 units、ドッキングは Core の解析判定＋補間
- 描画は Nearfield 段 [0.01, 100]（10m〜100km）が主。遠方は Near 段だが、km 級のステーションでも 500 units 先で数画素なので、**遠景は発光の光点で作る**ことになる
- 1 unit = 1 km。**メートル単位のモデルはスケール 0.001**（コックピットの 1000 倍空間とは逆方向。ステーションは実スケールの世界に置く）
- Demo 3 で確立済みの道具をそのまま使う: ThirdParty の追跡除外（.gitignore ＋追跡0件テスト）/ ImportPackageImmediately のリフレクション呼び（pathname 書き換え、gzip.GzipFile 経由）/ URP 変換は Converters.RunInBatchMode ではなく MaterialUpgrader（17.3.0 の Converters は必ず落ちる）/ PrefabUtility.InstantiatePrefab でリンク配置 / Editor スクリプトで new Material() しない（シーンに直列化され再配布問題が再発）/ レンダリングレイヤーは組み立ての最後に一度で配る / F4 の道具3つ（テスト柄・RT直接表示・表示面）
- Demo 3 の教訓を適用: 既定値が「無害な値」の設定は例外かテストで縛る / 対照を取ってから光の漏れを測る / 静止画で出ない欠陥があるので観測経路に動きを含める / 数値が全部緑で絵が駄目なら測る量の選び方を疑う
- 音のイベント（Docking 接合音 / Docked 確認音 / Undock クランプ解除 / Approaching 通知）は Demo 2 で実装済み。演出はこれに視覚を重ねる

## 3. Step 13-1：StationDefinition と調達（1日）

### 13-1a StationDefinition（Core、UnityEngine 非依存）

CockpitDefinition と対にする。**ステーションごとの定数をグローバルから定義側へ移す**のが本丸。

```
StationDefinition
  Id                "hirez-box" / "nasa-iss" / "cobble" ...
  PrefabGuid        （Box は null）
  Scale             m→units 0.001 ×（13-3 で確定する補正）
  PortLocal         ポート位置（プレハブ原点基準）
  PortForward/Up    ポート正面と上（EyeForward/EyeUp と同じ2軸方式）
  PortStandoff      既定 0.3 → 定義ごと（ISS なら 0.03 級まで下げる）
  RequestRange      要求可能距離（既定 20）
  NavLights[]       { 位置, 色, 点滅周期, 位相 }
  WindowEmissives[] { マテリアル名, 強度 }
  Fallback          Box
```

- 既存の解析判定・補間・セーブは StationDefinition から値を読む形に置き換え、**既定値で現行の数値と厳密一致**することを EditMode の数表で縛る（リファクタで挙動を変えない）
- Standoff を小さくするときの制約を数表に残す: ドッキング後のカメラ〜構造物の距離が Nearfield の near 0.01 units（10m）を下回らないこと

### 13-1b 調達（路線で分岐）

- **NASA 路線**: glTF の取り込みに com.unity.cloud.gltfast を追加（バージョン固定、12-0 と同様にパッケージ差分の混入を確認）。**追跡方針をここで決める**: パブリックドメインなので追跡可能だが、容量次第で source_assets/ ＋復元スクリプトに置く選択もある。クレジットは README に NASA の出典行（ガイドライン上、NASA の後援を示唆しない表現にする）
- **Cobble 路線**: GUI ホップ1回でダウンロード → 削除リストに **HDRP / Built-in のフォルダを最初から入れる**（1.8GB のうち URP に要る分だけ残す。インポート時間と Library 容量に直撃するため、削除リスト→取り込みの順を守る）
- どちらも docs/asset-sources.md に記録。番人テスト（追跡0件 or 許可リスト）を先にコミットしてから取り込む

テスト: 数表（既定値の厳密一致）/ 追跡の番人 / 取り込み後のレンダラー数 > 0 / 全マテリアルが URP

コミット目安: 13-0b / 13-1a / 13-1b の3回

## 5. Step 13-3：配置・スケール・ポート定義（1日）

- **実寸の確定**: バウンディングボックスの実測と 13-0 で決めた目標寸法から Scale を確定。目安の物差しは「ドッキング口の開口が船の全幅の 1.5〜3 倍」（船側の寸法は Hi-Rez の実測から出す）
- **ポートの置き場**: 外周に開けた面で、接近経路（±30 度の円錐）に構造物が被らない場所。船に衝突判定は無いので**すり抜け自体は起きないが、補間中に構造物を貫通して見えたら台無し**。CockpitVisibilityProbe と同型の「ポート正面からのレイが Standoff 距離まで構造に当たらない」プローブを Editor に作り、数値で縛る
- **姿勢**: 太陽電池パネルを太陽方向に向ける（位相角 90 度の配置なので、パネル法線＝太陽方向は定数で決まる）。明暗境界線ビューでの見栄えを F4 で振って確定
- **AP 到着方向との関係**: 現行は到着方向（＋X）とポート正面（−Y）が 90 度違い、手動で機首を向ける手順が残る。これを「操作として残す」か「ポートを到着方向に向けて省く」か、ここで決めて §0-A に記録（チルゲーとしては残す＝到着後にひと呼吸ある、を推奨。ただし決めるのは実機で試してから）
- 地球・火星は同じモデルの別インスタンス（Definition は共有し、位置・姿勢だけ配置側）。差別化（色・灯の周期）は 13-4 の定数で

テスト: Scale・Port の数表 / 接近円錐プローブ 0 件 / 往復の受け入れ（Demo 1 のシナリオ）が両ステーションで従来どおり

コミット目安: 2回（配置スケール / ポートと姿勢）

## 6. Step 13-4：遠景と発光（1日)

### 13-4a 遠景（光点→シルエット→構造）

- 惑星の LOD と同じ考え方で、**発光ビーコン（小球 or ビルボード）**を距離帯で出す: 例 2,000 units 以遠は光点のみ、2,000〜200 でビーコン＋メッシュのフェード、200 以下はメッシュのみ。閾値は F4 で振って決める（角直径と画素数を F1 に出す）
- アルファ合計 1.0 の縛り（惑星 LOD と同じテスト形式）

### 13-4b 発光と航法灯

- 窓の発光: 棚卸しで特定したマテリアルに MaterialPropertyBlock で発光を足す（**マテリアル複製はしない**。Demo 3 の ST 方式と同じ流儀）。強度は bloom しきい値 0.90 との関係を F4 で（画面の発光 0.75 と同じ決め方）
- 航法灯: 赤・緑・白の小さな発光球を NavLights[] から生成。点滅は UniverseClock の時刻から位相を引く（フレームレート非依存。Demo 2 の雲回転と同じ形式）。点滅周期は実在の衝突防止灯に寄せて 1〜2 秒
- 対照を取る: 発光を足す前後で「ステーション領域の外」の画素が動かないこと（bloom 経由の持ち上がりを Demo 3 の教訓どおり内外分離で測る）

テスト: アルファ合計 / 点滅の位相数表 / 時刻を進めたときの明滅（画素）/ 外領域 0px

コミット目安: 2回

## 7. Step 13-5：ドッキング演出（1日）

状態はすべて既存（Free / Approaching / DockRequested / Docking / Docked / Undocking）。**新しい状態は作らず、既存状態に視覚を紐付けるだけ**。

- DockRequested: ポートへの誘導灯列（ポート正面の線上に等間隔の発光球、Standoff の外から点灯）。ずれ角に応じて色（赤→黄→緑、整列 30 度以内で緑）。色の決定は Core の純関数（ずれ角→色）にして数表で縛る
- Docking（補間中）: 誘導灯を収束パターンに、接合音（既存）と同期して構造物側の照明を1段明るく
- Docked: 窓の外にベイ構造が見える位置関係を 13-3 のポート定義で保証。微振動 0（既存挙動）
- Undocking: クランプ解除音（既存）と同時に誘導灯消灯
- 要求NG（距離・角度）: 誘導灯を出さない。F1 の表示は現行のまま

テスト: 状態→灯の対応表（EditMode 数表）/ 各状態のスクショで誘導灯領域の画素検証 / ずれ角を振ったときの色遷移

コミット目安: 1回

## 10. Demo 4 で「やらない」こと（要決定として記録）

- ステーションの自転・軌道運動（惑星位置固定と同じ理由）
- ベイ内部への進入（ドッキングは外部ポート方式。内部格納は徒歩・船内歩行と同じく範囲外）
- 船側の着陸脚・ドッキング機構のアニメーション
- ステーションの衝突判定（解析判定のまま。接近円錐プローブで見た目の貫通だけ防ぐ）
- 管制の音声・無線（テキスト通信＝予定 14 で扱う）
- 有料アセットの購入判断は 13-2 の棚卸し後に必要なら実施（Demo 3 の 11-5 と同じゲート形式）

## 11. リスク

| リスク | 対策 |
|---|---|
| Cobble 1.8GB でインポートが長時間化 | 削除リスト（HDRP / Built-in）を取り込み前に適用。取り込み時間を計測して §0-B 系の表に記録 |
| gltfast が意図しない依存を連れてくる | 12-0 と同じ「パッケージ差分の確認」をゲートに。lock の差分をコミットに明記 |
| モデルのピボットが中心でない / 軸が想定外 | 13-2 で記録し、PortLocal / PortForward で吸収（プレハブの回転では吸収しない。Demo 3 の EyeForward と同じ理由） |
| ポート付近の構造で補間中に貫通して見える | 接近円錐プローブで事前検出。ポート候補を変えても駄目ならモデルの向きを変える |
| Standoff を下げすぎて Nearfield near 0.01（10m）を切る | 13-1a の数表に制約として明記 |
| 発光で bloom が持ち上がり惑星・計器の確定値が崩れる | 内外分離の対照測定（Demo 3 の教訓）。画面の発光 0.75・bloom 3.00 は据え置き、ステーション側の強度で吸収 |
| 発光マテリアルが構造体と共有されていて窓だけ光らせられない | MaterialPropertyBlock ＋レンダラー単位の指定で分離。それでも無理なら実行時複製＋OnDestroy 破棄（Demo 3 の流儀） |
| 新シェーダ（誘導灯等）を書いて XR で片目落ち | SPI マクロ規約のテスト（シェーダファイルにマクロと pragma があること）を 13-5 で追加 |
| 遠景の光点が星と紛らわしい | 点滅で区別（星は瞬かない設計のまま）。それ自体を演出にする |
| ISS 路線で「火星に ISS」の違和感 | 「ISS モジュールで組んだ火星軌道ステーション」として灯の色・周期で差別化。それでも気になるなら火星側だけ将来 SF に差し替えられるよう Definition を分けておく |

## 1. 前提（現状の構成と守ること）

- コックピットは実寸 5.5e-4〜2.2e-3 units で near 0.01 のクランプに負けるため、**1000 倍の描画空間**で組んである（Cam_Cockpit: near 0.1 / far 100、専用レイヤー、Overlay depth3、深度クリア）。**1 m の実物 = 0.001 km = 1000 倍空間で 1 unit** なので、メートル単位で作られたアセットは **スケール 1 のまま**この空間に置ける
- 階層は Ship → CockpitRig（微振動、回転 1.5e-3 rad）→ Cam_Cockpit と Cockpit(枠) の両方がその子
- 計器パネルは 768×160 の Render Texture を下端の帯に貼っている（背景アルファ 0.55）。文字は TextMeshPro
- ポストプロセスは Cam_Cockpit の設定で一度だけ適用（bloom 3.00 / しきい値 0.90 / 拡散 0.70 / vignette 0.22）。**発光 0.90 超はすべて滲む**
- 光源は Directional 1 灯（強度 3.0）。コックピット層への照明は未整理
- リポジトリは PUBLIC。**Asset Store の EULA はアセットの再配布を禁じるため、取り込んだアセットは追跡してはならない**
- 検証ハーネス: -scenario / F1 / F4（38 項目）/ ScenarioCapture / StandaloneCapture。batchmode の RT スクショにコックピット層は写る（Step 6 で箱が写っている）

## 3. Step 11-0：調達とライセンスの整理（0.5 日）

### 11-0a 無料サンプルの取得（GUI が必要な唯一のホップ）

## 4. Step 11-1：取り込みと URP 変換（1 日）

### 11-1a batchmode 取り込み
- Editor スクリプト `CockpitImporter.Import(packagePath)`: ImportPackageImmediately → 取り込み結果のファイル一覧をログ → プレハブ GUID を `CockpitDefinition` に記録
- 取り込み後に **不要物を削除**: デモシーン、Built-in 専用のポストプロセス、サンプルスクリプト（コンパイルエラーの温床）。削除リストは定義ファイルに持ち、再取り込みしても同じ結果になるようにする

### 11-1b URP 変換
- Built-in の Standard マテリアルは URP で桃色になる。**URP の Render Pipeline Converter は batch 用 API を持つ**（`UnityEditor.Rendering.Universal.Converters.RunInBatchMode(ConverterContainerId.BuiltInToURP)`）ので、これを Editor スクリプトから呼ぶ。GUI は使わない
- 変換後の確認（EditMode）: ThirdParty 配下の全マテリアルの shader 名が `Universal Render Pipeline/` で始まる。1 件でも Standard が残れば失敗
- Hi-Rez は URP 対応と明記されているため、変換は「何もしないで通る」可能性が高い。**それでも同じ経路を通しておく**（有料アセットで必ず要る）

### 11-1c マテリアルの棚卸し
- ログに「マテリアル名 / シェーダ / 発光の有無 / 参照メッシュ数」を出し、**画面用マテリアル**と**発光（ボタン・インジケータ）**を特定する。この結果を 11-3 の入力にする
- Hi-Rez の場合、「画面はプレースホルダー」なので画面テクスチャを差し替える前提。画面のマテリアルが他と共有されている場合は複製して独立させる（共有のままだと Render Texture が内壁にも映る）

テスト
- EditMode: 取り込み後のプレハブが存在しレンダラー数 > 0 / 全マテリアルが URP / 削除リストのファイルが存在しない / ThirdParty が未追跡
- PlayMode: 起動してコックピット層に描画されるレンダラー数が箱のときより多い（差し替わっている）

コミット目安: 11-1 で 1 回

## 5. Step 11-2：配置・スケール・視点（1 日）

### 11-2a CockpitDefinition（Core、UnityEngine 非依存）
将来の船乗り換えの拡張点をここで作る。1 隻＝1 定義。
```
CockpitDefinition
  Id              "hirez-sample" / "box"
  PrefabGuid      アセットのプレハブ（Box は null）
  Scale           1.0（メートル単位のアセット）
  EyeLocal        座席の目の位置（プレハブ原点基準、m）
  EyeForward      機首方向（プレハブの軸が Z+ でないことがある）
  Screens[]       { MaterialName, RenderTextureRole }  ← 11-3 で使う
  Emissives[]     { MaterialName, DefaultIntensity }  ← 11-4 で使う
  Fallback        Box
```
- 既定値は Core の定数（Demo 2 の PlanetAppearance.cs と同じ「二重定義しない」流儀）
- SceneBuilder は Definition から CockpitRig の下にプレハブを置き、Cam_Cockpit を EyeLocal に置く。**箱と同じ手順で組めること**がテストの対象

### 11-2b 目の位置と向き
- 座席位置はアセットのデモシーンから拾えない（削除済み）ので、**プレハブのバウンディングボックスから初期値を出し、F4 で振って決める**
- F4 に追加する項目: 目の高さ / 前後 / 左右（各 ±0.5 m、0.01 刻み）、カメラ FOV（現状値を既定、50〜90°）。閉じたときのログを定数へ
- 決める基準（チルゲー）: 正面窓の上端が画面上端より上にあり、計器盤の上端が画面の下 1/3 より下にあること。**「窓が視界の何 % を占めるか」を数値で出す**: 窓マテリアル（またはキャノピー透過部）の投影面積 / 画面面積。ハーネスのシナリオ `cockpit-view` で算出し F4 の天体行と同じ形式で表示

### 11-2c 軸とスケールの検証
- アセットの前方軸が Z+ でない場合、EyeForward で吸収する（プレハブの回転で吸収するとテストが「回転の存在」に依存する）
- 実寸確認: 計器盤の幅・座席の高さがメートル相当かどうか。Hi-Rez は「モジュールを自由に拡縮する」思想なのでスケール 1 が実寸とは限らない。**目安は「操縦桿の高さ 0.6〜0.8 m」**。ずれていれば Definition.Scale で吸収

### 11-2d 4 段カメラとの整合
- コックピット層は深度クリアの Overlay なので、モデルがどれだけ大きくても他の層を隠す以外の副作用はない。逆に**キャノピーのガラスが不透明マテリアルだと外が見えない**。ガラスは Transparent に変換されていることを 11-1c の棚卸しで確認
- ガラスに反射がある場合、反射プローブが無いので黒く映る。Demo 3 では**ガラスの反射は切る**（Smoothness を落とす）。反射プローブは要決定に記録

テスト
- EditMode: Definition の既定値表 / 箱と Hi-Rez の両定義で SceneBuilder が同じ手順を通る / EyeLocal がプレハブの bounds 内
- PlayMode（画素）: `cockpit-view` シナリオで窓の投影面積比が既定範囲（目視で決めた値 ±5%）/ 窓の中に地球（earth-close-day の位置）が見える＝窓領域の平均色が黒でない

完了条件
- 箱と同じ位置・同じ向きで、窓の外に地球が見える

コミット目安: 11-2a〜b / 11-2c〜d の 2 回

## 6. Step 11-3：計器の画面への移設（1〜1.5 日）

### 11-3a 画面の割り当て
- 現在の 768×160 パネル 1 枚を、**役割別の Render Texture 2〜3 枚**に分ける。Definition.Screens の RenderTextureRole で対応付ける
  - Primary（正面の主画面）: SPD / DST / ETA
  - Target（副画面）: TGT / ALN / ドッキング状態（Free〜Docked）
  - Status（小画面、あれば）: 速度ダイヤル段 / AP 状態 / 音の行（F1 の「音」行と同じ）
- 画面が 1 枚しかないアセットなら Primary に 2 行構成で詰める。**役割→画面の対応は Definition に持ち、コードは役割だけを見る**

### 11-3b Render Texture と発光
- 画面マテリアルの `_BaseMap` と `_EmissionMap` の両方に RT を割り当て、`_EmissionColor` を HDR で調整。**発光強度は bloom しきい値 0.90 の下（0.6〜0.85）を既定**にし、文字が滲まないことを優先。F4 の「画面の発光」で振る
- 文字色は現在の緑〜シアン系を継続。背景は不透明黒（アルファ 0.55 の帯は廃止。画面はモデルに埋め込まれているので透ける必要がない）
- RT の解像度は画面の投影サイズから決める: 画面が画面上で W px なら RT 幅は 2W 以上（TMP の滲み防止）。`cockpit-view` シナリオで投影サイズを実測してから決める

### 11-3c 下端の帯の撤去
- 帯の Quad と 768×160 RT を撤去。**撤去はリフレクションで再発を縛る**（Demo 2 の EngineAudio 撤去と同じ）
- Box フォールバックのときだけ帯を残す（箱には画面が無い）。Definition の Screens が空なら帯、というルールにする

テスト
- EditMode: 役割→画面の対応表 / 帯の有無が Screens.Length で決まる / RT の解像度が投影サイズの規則を満たす
- PlayMode（画素）: 画面領域の中に TMP の文字色（緑〜シアン）の画素が一定割合ある / 画面外の内壁にその色が漏れていない（画面マテリアルの分離が効いている）/ 太陽正面（sun-face）で画面の文字が bloom で潰れていない＝文字領域の輝度分散が閾値以上

完了条件
- 計器の情報が画面の中に収まり、帯が消える

コミット目安: 11-3a〜b / 11-3c の 2 回

## 7. Step 11-4：照明（0.5〜1 日）

### 11-4a 太陽光の差し込み
- Directional Light はレイヤーに関係なく当たるので、コックピット層にも既に当たっている。問題は **影**: コックピット層は Overlay で深度クリアするため、他の層の影は落ちない。コックピット内の影（計器盤に落ちる窓枠の影）は Directional の Shadow が Cockpit 層で有効なら出る。URP の Light の culling mask とシャドウ距離（1000 倍空間なので far 100 以内で十分）を確認
- 太陽の方向は船の姿勢で変わり、CockpitRig は Ship の子なので追加処理なし。**earth-terminator / sun-face / sun-hidden の 3 シナリオでコックピット内の明るさが変わる**ことを画素で確認

### 11-4b 画面の照り返しと補助光
- 画面の発光は内壁を照らさない（Emission はライトではない）。**Point Light 1 灯**（culling mask = Cockpit 層のみ、強度は弱く、色は画面の色）を主画面の前に置いて「照り返し」を表現。F4 に「補助光の強さ」を追加、既定は太陽が後ろのとき（sun-hidden）に計器盤の輪郭が見える最小値
- 発光マテリアル（ボタン・インジケータ、Definition.Emissives）は既定強度 0.3〜0.6。bloom で滲ませたいものだけ 0.9 超。**「見えないコードは残さない」**: 発光の無いアセットなら Emissives は空

### 11-4c ポストプロセスとの相互作用
- bloom 3.00 は太陽用に決めた値で、画面の文字には強すぎる可能性がある。**11-3 で画面の発光を下げて対処し、bloom は変えない**（太陽の見た目を再測定しないため）。それでも潰れるなら要決定に記録して Demo 4 で扱う
- vignette 0.22 は窓枠と重なると二重の暗さになる。実機で見て 0.22 → 0.10〜0.15 の再検討を許容（変えるなら代表カット 3 枚の再撮影）

テスト
- EditMode: Point Light の culling mask が Cockpit 層のみ / Directional の shadow 設定
- PlayMode（画素）: sun-face と sun-hidden で計器盤領域の平均輝度に差がある / sun-hidden で計器盤の輪郭が黒潰れしていない（輝度 > 0 の画素比）

完了条件
- 太陽が窓から差すと影が動き、太陽が後ろでも計器盤が見える

コミット目安: 11-4 で 1 回

## 12. リスク

| リスク | 対策 |
|---|---|
| アセットが public リポジトリに乗る | 11-0 の .gitignore とテストを最初に。取り込みは追跡除外のコミット後 |

| アセットのスクリプトがコンパイルエラーになる | 11-1a の削除リストで先に消す。スクリプトは一切使わない前提 |

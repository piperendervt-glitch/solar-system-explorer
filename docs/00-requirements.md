# 依頼：太陽系探索チルゲー「最小デモ」の設計

以下の前提とステップ計画に基づき、**最小デモの技術設計**を行ってください。実装コードはまだ不要です。設計が固まったら、その後のチャットでステップごとに実装を依頼します。

---

## 1. プロジェクトの目的

- 「美しいグラフィックスで、宇宙空間を宇宙船で移動する」ことがメインの**チルゲー**
- Star Citizen のようなリアル寄りの見た目を目指すが、中身は宇宙飛行シム
- 個人で楽しむデモ。本格的な公開・販売は現時点では考えていない
- 操作の楽しさより「眺めの美しさと静けさ」を優先する

## 2. 開発環境

- Unity 6（URP）
- Input System パッケージ
- Git 管理
- 開発機：Lenovo Legion（RTX 5060 Ti 16GB、RAM 32GB、Ryzen 7 8745HX）
- 3D モデルは公開アセット（Unity Asset Store、Sketchfab、Kenney、NASA テクスチャ等）を活用する

## 3. 決定済みの設計方針

| 項目 | 決定内容 |
|---|---|
| 単位系 | 1 Unity unit = 1 km |
| 座標 | プレイヤー絶対位置は double 精度で保持。浮動原点（floating origin）でシーンをシフト |
| 移動時間 | **等倍時間で待つ**（時間圧縮・ワープなし） |
| 巡航速度 | 可変。デフォルト 0.1c、最大 1.0c |
| 相対論的効果 | **今回は実装しない**（後から視覚シェーダとして追加できる構造にしておく） |
| 惑星位置 | 固定（公転なし） |
| 移動操作 | オートパイロット（目標選択→自動で向いて巡航）が主、手動操作（ピッチ・ヨー・ロール・前進）が従 |
| 船の物理 | Rigidbody 不使用。自前で速度積分（kinematic） |
| アセット予算 | 星空 HDRI とコックピット計器の見た目に集中投資 |

## 4. 最小デモのゴール

**地球ステーションを出発 → 火星ステーションにドッキング。コックピット視点で計器を見ながら。**

### 含めるもの
- 浮動原点
- 太陽・地球・火星（固定位置、NASA テクスチャ、遠方は光点・接近で本メッシュに切替）
- 宇宙船 1 隻（コックピット視点固定、速度ダイヤル 0.1c〜1.0c、オートパイロット＋手動）
- コックピット計器（Render Texture + TextMeshPro）：速度（c 表記）、目標距離、ETA など 3〜4 項目
- ステーション 2 基（地球・火星）とドッキング（Trigger 進入→要求表示→キーで停止・補間→ドッキング状態→キーで出港）
- 見た目の仕上げ：星空 HDRI、控えめなポストプロセス、太陽フレア、エンジンのアンビエント音
- （任意）ドッキング時に現在ステーション名だけ JSON セーブし、起動時にそこから開始

### 最小デモから外すもの（今後検討）
- 宇宙船の乗り換え（本設計で追加予定）
- 相対論的効果、ワープ
- プレイヤーキャラクター／NPC の描画、NPC 会話
- 惑星・衛星への着陸、ステーション内・船内の徒歩移動
- PCVR
- 船の修理・購入、仕事、敵・戦闘

## 5. ステップ計画（この順序で実装予定）

| Step | 内容 | 完了条件 |
|---|---|---|
| 0 | プロジェクト準備（Unity 6 + URP、Input System、Git、単位系統一） | 空シーンでカメラが動く |
| 1 | 浮動原点（絶対位置 double、閾値超過で全オブジェクトを逆シフト） | 1c 相当で 10 分飛んでもジッター・Z ファイトが出ない |
| 2 | 太陽系プレースホルダー（太陽＝Directional Light＋発光球、地球・火星、光点⇔メッシュ切替） | 地球から火星が「星」に見え、近づくと惑星になる |
| 3 | 宇宙船の移動（速度ダイヤル、手動操作、オートパイロット） | 火星を選択→放置で数分後に到着圏内 |
| 4 | コックピットと計器 | 計器がリアルタイム更新される |
| 5 | ステーションとドッキング | 地球⇔火星を往復できる |
| 6 | 見た目の仕上げ | 眺めていて気持ちいいと感じる |
| 7 | セーブ（任意） | 起動時に前回ドッキング先から開始 |

Step 1 が最重要。ここが失敗すると後がすべてやり直しになるため、最初に潰す。

## 6. 設計として出力してほしいもの

1. **全体アーキテクチャ**：主要クラス／コンポーネントの一覧と責務、依存関係（Mermaid 等の図があると望ましい）
2. **浮動原点の詳細設計**：double 座標の持ち方、シフト閾値、シフト対象の管理方法、惑星・ステーション・船・カメラ・パーティクル・Trail など各要素のシフト時の扱い、テスト方法
3. **太陽系のスケール設計**：AU→km 換算、各天体の実寸と配置、光点⇔メッシュ切替の距離と方法、Directional Light の扱い（太陽方向の計算）
4. **船の移動モデル**：速度の保持形式（c の正規化値と km/s）、加減速の有無、オートパイロットの状態遷移、手動操作との切替
5. **計器の設計**：Render Texture 構成、表示項目と更新頻度、ETA の計算式
6. **ドッキングの状態遷移**：Free / Approaching / DockRequested / Docking / Docked / Undocking の各状態と遷移条件
7. **シーン構成とプレハブ設計**：シーン分割の要否、プレハブの粒度、アセット差し替えを容易にする構造
8. **後から相対論効果と船乗り換えを追加するための拡張ポイント**：今のうちに用意しておくべきインターフェースやデータ構造
9. **推奨アセット候補**：コックピット、ステーション、星空 HDRI、惑星テクスチャ、環境音について、入手元とライセンスの目安
10. **リスクと落とし穴**：浮動原点まわり、URP でのスケール差、float 精度が漏れる箇所など

## 7. 設計上のお願い

- 「個人デモ」なので、過剰な汎用化より**シンプルで壊れにくい構造**を優先してください
- 各ステップが独立して動作確認できるよう、ステップ間の依存を最小にしてください
- 判断が分かれる箇所は、選択肢と推奨理由を示してください
- 不明点があれば、設計を進める前に質問してください
